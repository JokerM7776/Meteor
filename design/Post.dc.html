Building a zero-JS blog with vanilla PHP

One entry file, a regex router, PDO and output buffering. How far plain PHP 8 gets you before you miss a framework.

Published 12 Oct 2026 8 min read #php #architecture #zero-js

Most blogs ship more JavaScript than words. This one ships none. The public pages are rendered by about two thousand lines of plain PHP, the CSS fits in a single file, and a post loads in one request.

Here is how the pieces fit together, and where the edges are.

One entry point

Every request is rewritten to public/index.php. The router reads the path, peels off the language prefix and matches the rest against a short list of patterns.

PHP is already a template engine

Views are plain .php files. Output buffering captures a page view, and the master layout echoes it between the header and footer partials.

The fastest code on a page load is the code that already ran when you pressed Save.

Compile on save

Markdown is converted to HTML once, in the admin panel. The public site only reads three columns:

  • content_html — the article body, ready to echo
  • toc_html — the anchor list you see on the right
  • summary — the excerpt and meta description

One post, many languages

A post is one row in posts and one row per language in post_translations. A second, tiny query lists the other published locales, which become the links at the top of this page and the hreflang tags in its head.
